Project overview · Architecture

OpenHouse

A full-stack listing and reservation platform where people offer places to stay and vehicles (homes, tents, containers, caravans, cars, buses and more) and others find them by city and capacity and apply to use them. Built with Next.js and MongoDB, packaged with Docker and self-hosted on a Raspberry Pi 5.

What it does

The main user flows, each backed by its own API route and database model.

Browse & search

Listings by category on the home page; a search modal filters by province, district and guest capacity through URL query parameters, and the results are rendered on the server.

List a place or vehicle

An 8-step wizard collects category, map location, address, vehicle specs, capacity, photos (uploaded to Cloudinary), description and availability dates.

Apply for a listing

Signed-in users send one application per listing for its availability window; the owner is notified by email and both sides track it in their dashboards.

Accounts

Sign in with Google or register with email and a bcrypt-hashed password. Sessions are stateless JWTs.

Favorites & dashboards

Save listings to favorites; manage My trips, My reservations and My properties. These routes are protected by middleware.

Maps

Leaflet with OpenStreetMap tiles shows each listing's location, with a country and Turkish province/district picker for addresses.

Life of a reservation

What happens when a guest applies for a listing.

  1. View. The listing page is rendered on the server with the listing, its owner, its availability window and its existing reservations.
  2. Check. The client opens the login modal for anonymous users and blocks a second application from the same user.
  3. Submit. The client posts to /openhouse/api/reservations via an Axios client that prefixes the base path.
  4. Authenticate. The route handler reads the NextAuth JWT session to identify the current user and rejects anonymous requests.
  5. Persist. Prisma creates the Reservation document, linked to the user and the listing, in MongoDB.
  6. Notify. Nodemailer emails the listing's owner about the new booking.
  7. Confirm. A toast confirms the request and the guest is taken to their reservations dashboard.

Engineering decisions

Choices made to run a production-style deployment on a single-board computer.

Served under a sub-path

The app is built with a Next.js basePath of /openhouse, so it lives next to my portfolio on the same domain. API calls go through one Axios client that adds the prefix.

Small, multi-arch image

A three-stage Dockerfile builds Next.js in standalone mode and ships only the traced runtime files, running as a non-root user. buildx publishes amd64 and arm64 images.

Self-hosted database

Migrated from MongoDB Atlas with mongodump/mongorestore. MongoDB runs as a one-node replica set, which Prisma needs for its writes, and is unreachable outside Docker.

Ordered startup

A health check initialises the replica set and reports healthy only once the node is primary. The app waits for it, then runs prisma db push to sync indexes.

No open ports

Cloudflare Tunnel makes an outbound connection from the Pi, so no router port-forwarding is needed and TLS is handled at Cloudflare.

Light on the Pi

Images are already sized by Cloudinary and Google, so the Next.js image optimiser is turned off to save CPU on the device.
